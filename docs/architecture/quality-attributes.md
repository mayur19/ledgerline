## Trade-offs

- **Gapless numbering vs throughput (QA-04 vs QA-09).** The sequence row lock serialises posting per entity and fiscal year. We accept a ceiling of a few hundred posts per second per entity; bulk imports (LL-039) will reserve number blocks inside one transaction.
- **Strict validation vs convenience.** Amounts with excess precision are rejected rather than rounded so user input is never silently changed; the UI flags it while typing.
- **In-process throttles vs scale-out (QA-11).** Correct for one instance only; LL-100 moves counters to Postgres before a second instance is allowed.
